## ২. সমস্যার তালিকা (গুরুত্ব অনুযায়ী)

গুরুত্ব: **উচ্চ** = লাইভে ক্ষতি বা আইনি ঝুঁকি · **মাঝারি** = ঠিক না করলে ঝুঁকি বাড়ে · **নিম্ন** = উন্নতি।

### উচ্চ

**F-01 কর্মী মুছলে তার পরিশোধিত বেতনের সব রেকর্ডও মুছে যায়** (AUD-02)
- ধাপ: কর্মী বানান → salary structure → payroll তৈরি, approve ও pay করুন → `DELETE /api/employees/:id`।
- ফল: `200 success`। এরপর `payrolls` টেবিলে ওই কর্মীর **0 সারি**, `all_employees`-এও নেই।
- মজার ব্যাপার: পরিশোধিত payroll **সম্পাদনা** করা যায় না ("A Paid payroll run can't be edited") — কিন্তু মুছে ফেলা যায়।
- ঝুঁকি: শ্রম আইন ও অডিটে বেতনের রেকর্ড কয়েক বছর রাখতে হয়। Employees মডিউলের একজন Admin ভুলে বা ইচ্ছা করে ইতিহাস মুছতে পারে।
- সমাধান: payroll, leave বা settlement থাকলে মোছা বন্ধ করুন, বদলে `is_active = 0` (নিষ্ক্রিয়)। সঙ্গে foreign key-তে `ON DELETE RESTRICT`।

**F-02 Notice-এর HTML পরিষ্কার করা হয় না (Stored XSS)** (SEC-17)
- ধাপ: Notices মডিউল আছে এমন Admin `<img src=x onerror="...">` সহ notice দিন → কর্মীর `GET /api/notices/board`-এ হুবহু ফেরত আসে।
- `NoticeBoard.tsx`, `NoticePopup.tsx`, `TrackingNoticeCard.tsx` এটা `dangerouslySetInnerHTML` দিয়ে আঁকে।
- ঝুঁকি: লগইন token ব্রাউজারের `localStorage`-এ থাকে (`mpr_token`)। তাই এই স্ক্রিপ্ট যে কর্মীর পেজে চলবে, তার (এমনকি Superadmin-এর) অ্যাকাউন্ট দখল করা যায়।
- সমাধান: সার্ভারে সেভ করার সময় HTML পরিষ্কার করুন (যেমন `sanitize-html`)। Credence Mail-এ আগেই `sanitizeMailHtml` আছে, একই ধাঁচ।

**F-03 বারবার ভুল পাসওয়ার্ড দিলেও আটকায় না** (SEC-03)
- ধাপ: একই অ্যাকাউন্টে ২৫ বার ভুল পাসওয়ার্ড। প্রতিবার `400`। এরপর সঠিক পাসওয়ার্ডে সঙ্গে সঙ্গে ঢোকা যায়।
- ঝুঁকি: পাসওয়ার্ড অনুমান করে (brute force) অ্যাকাউন্ট দখল।
- সমাধান: IP ও অ্যাকাউন্ট ধরে লগইনে rate limit (যেমন ৫ বার ভুলের পর ১৫ মিনিট), অথবা ক্রমবর্ধমান বিলম্ব।

### মাঝারি

**F-04 একই তারিখে একাধিক ছুটির আবেদন নেওয়া হয়, প্রতিটিতে ব্যালেন্স কাটে** (LEAVE-04, 05, 06)
- একই ১ দিনের জন্য দুটি Casual আবেদন: দুটোই `200`, ব্যালেন্স ৬ → ৪ (একদিনের ছুটিতে ২ দিন কাটা)।
- একই সময়ে ৩টি একই আবেদন পাঠালে ৩টিই তৈরি হয় (race condition)।
- Casual-এর সাথে ওভারল্যাপ করা Sick আবেদনও চলে যায়।
- ঝুঁকি: ব্যালেন্স ভুল, payroll-এর leave দিন ভুল, কর্মীর অভিযোগ।
- সমাধান: আবেদন নেওয়ার সময় ওই কর্মীর `pending/approved` আবেদনের সাথে তারিখ ওভারল্যাপ যাচাই; এবং `(user_id, তারিখ)`-এ ডাটাবেস লকের মতো সুরক্ষা।

**F-05 পাসওয়ার্ড বদলালেও পুরোনো token চলে** (SEC-10)
- `PUT /api/profile/password` সফল (200), কিন্তু পুরোনো token দিয়ে `/api/auth/me` তখনও `200`। token ১২ ঘণ্টা বৈধ।
- ঝুঁকি: চুরি যাওয়া token দিয়ে পাসওয়ার্ড বদলের পরও ঢোকা যায়। (ব্লক বা মুছে ফেলা অ্যাকাউন্ট কিন্তু ঠিকই আটকায়।)
- সমাধান: `users`-এ `token_version` রাখুন, পাসওয়ার্ড বদলালে বাড়ান; `authenticateToken` তা মেলাবে।

**F-06 যেকোনো ওয়েবসাইট API ডাকতে পারে, নিরাপত্তা header নেই** (SEC-11, 12)
- `Access-Control-Allow-Origin: *`। `Content-Security-Policy`, `X-Frame-Options`, `Strict-Transport-Security`, `X-Content-Type-Options` নেই।
- সমাধান: CORS-এ শুধু নিজের ডোমেইন; `helmet` যোগ করুন (CSP সাবধানে, কারণ Vite ও map tile লাগে)। Socket.IO-তেও `origin: "*"`।

**F-07 `JWT_SECRET` না থাকলে কোডের ভেতরের নির্দিষ্ট গোপন মান ব্যবহার হয়** (SEC-13)
- `server.ts:৯২`: `process.env.JWT_SECRET || "mpr_tracker_secret_key_2026"`। শুধু সতর্কবার্তা ছাপে, থামে না।
- ঝুঁকি: লাইভে `.env` ভুল হলে যে কেউ ওই মান দিয়ে Superadmin-এর token বানাতে পারে (কোড গিটে আছে)।
- সমাধান: `NODE_ENV=production` এ মান না থাকলে বা ছোট হলে সার্ভার চালু হতে দেবেন না।

**F-08 দুর্বল পাসওয়ার্ড নীতি** (SEC-07)
- শুধু "কমপক্ষে ৬ অক্ষর"। `111111` গ্রহণযোগ্য।
- সমাধান: কমপক্ষে ৮ অক্ষর, সাধারণ পাসওয়ার্ড তালিকা বাদ, প্রথম লগইনে বদলাতে বাধ্য করা।

**F-09 Payroll-এ উপস্থিতি দিন > কর্মদিবস গ্রহণ করে** (PAY-04)
- ২৬ কর্মদিবসের মাসে ৪০ দিন উপস্থিতি দিলেও payroll তৈরি হয় (`200`)।
- সমাধান: `present + leave + lwp ≤ total_working_days` যাচাই।

### নিম্ন

**F-10 কর্মীর তথ্য যাচাই কম** (EMP-02, 04)
- ইমেইল `not-an-email` নেয়। জন্মতারিখ ২০১৫ (বয়স ১১) নিয়েও কর্মী তৈরি হয়।
- সমাধান: ইমেইল ফরম্যাট; বয়স কমপক্ষে ১৪ (ঝুঁকিপূর্ণ কাজে ১৮) বাংলাদেশ শ্রম আইন অনুযায়ী যাচাই। নীতি আপনাদের HR ঠিক করবে।

**F-11 ভুল অনুরোধে HTML পাতা ফেরে, JSON নয়** (SEC-15, 16)
- ভাঙা JSON পাঠালে `400` কিন্তু Express-এর HTML ত্রুটি-পাতা (dev-এ ফাইল পথ সহ)। অজানা `/api/...` পথে `404` নয়, ওয়েব পেজ সহ `200`।
- সীমা বেশি হলে ডাটাবেসের কাঁচা বার্তা যায়: `Out of range value for column 'basic_salary'`।
- সমাধান: JSON error handler, `/api` এর অজানা পথে `404 {error}`, ডাটাবেস বার্তা মুখোশ।

**F-12 কর্মীর প্রতিটি পেজে ৩টি অপ্রয়োজনীয় 403** (UI স্মোক)
- Claims অনুমতি নেই এমন কর্মী কোনো পেজ খুললেই `/api/claims/status`, `/api/claims/mine`, `/api/user-claims/mine` ডাকে, প্রতিটিতে 403।
- ক্ষতি নেই, তবে লগ ভরে যায়, অকারণ রিকোয়েস্ট। সমাধান: অনুমতি না থাকলে ডাকবেন না।

## ৪. যা ঠিকভাবে কাজ করেছে (HR-এর দৃষ্টিতে)

- **নিয়োগ থেকে বিদায় পুরোটা:** জব পোস্টিং → প্রার্থী → hire → onboarding (১৪ ধাপ) → appointment letter → পদোন্নতি, বদলি, increment → পদত্যাগ → ছাড়পত্র → settlement → লগইন বন্ধ → HR-এর কাছে ৩৬০° রেকর্ড অক্ষত।
- **বেতন:** ৫৯ মাসের payroll, increment, Eid bonus, ঋণ-কর্তন, **net = gross − tax − PF − ঋণ + bonus** প্রতিবার মিলেছে (যেমন 50,000 − 500 − 1,500 = 48,000)।
  Audit অনুমোদন (Mahbub) ও Accounts পরিশোধ (Selina) আলাদা; **HR নিজের তৈরি payroll নিজে approve করতে পারে না**।
  পরিশোধিত মাস সম্পাদনা ও পুনরায় তৈরি দুটোই আটকায়। একই কর্মীর একই মাস দুবার হয় না। যোগদানের আগের মাসে বেতন হয় না।
- **অনুমতি:** কর্মী Admin-এর কোনো পেজ বা API খুলতে পারে না (৬টি পড়ার API আর ৭টি লেখার API-তে ঢুকতে দেয় না)। কর্মী নিজের role বাড়াতে পারে না (mass assignment)।
  সীমিত Admin নিজেকে বেশি অনুমতি দিতে পারে না। অনুমতি ছাড়া Payroll পড়া যায় না। দ্বিতীয় Superadmin API দিয়ে বানানো যায় না।
- **গোপনীয়তা:** কর্মীর ছুটির তালিকায় সহকর্মীর আবেদন দেখা যায় না। নিজের ছুটি নিজে অনুমোদন বা অনুমোদনকারী নয় এমন সহকর্মী অনুমোদন করতে পারে না। কর্মী অন্যের payslip পায় না।
- **নিরাপত্তার ভিত্তি:** SQL injection আটকায়, নকল/অস্বাক্ষরিত (`alg=none`) token আটকায়, পাসওয়ার্ড bcrypt, ব্যবহারকারী তালিকায় hash নেই, ভুল ইউজার ও ভুল পাসওয়ার্ডে একই বার্তা (অ্যাকাউন্ট আন্দাজ করা যায় না), ৩০MB অনুরোধ আটকায়।
- **নিরীক্ষা লগ:** কর্মীর তথ্য বদলালে `employee_change_log`-এ লেখা হয়। ব্লক/মুছে ফেলা অ্যাকাউন্টের সব সেশন সঙ্গে সঙ্গে বন্ধ হয়।
- **ছুটির ব্যালেন্স:** ব্যালেন্সের বেশি আবেদন, শেষ তারিখ শুরুর আগে, কারণ ছাড়া, অচেনা ছুটির ধরন, সবই আটকায়। নেগেটিভ বোনাস ও নেগেটিভ বেতন আটকায়।
- **UI:** Superadmin-এর ৭১টি পেজ (সব Admin Panel ট্যাব + Self Service) ডেস্কটপ ও মোবাইলে কোনো JavaScript ত্রুটি, অনুভূমিক scroll বা ফাঁকা পেজ ছাড়া খোলে। সবচেয়ে ধীর পেজ Admin Dashboard (~৭ সেকেন্ড, প্রথমবার ঠান্ডা লোডে)।
