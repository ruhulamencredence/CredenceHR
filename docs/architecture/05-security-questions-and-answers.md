# নিরাপত্তা নিয়ে প্রশ্ন করলে কী উত্তর দেবেন (প্রশ্ন-উত্তর)

> ক্লায়েন্ট, অডিটর বা ম্যানেজমেন্ট যেসব প্রশ্ন সাধারণত করে, তার উত্তর। প্রতিটি উত্তরের পাশে অবস্থা:
> ✅ **আছে** (কোড/টেস্টে প্রমাণসহ) · ⚠️ **আংশিক** · ❌ **নেই** · 🏢 **প্রতিষ্ঠান/হোস্টিংয়ের ব্যাপার** (সফটওয়্যারের কোডে নয়, আপনাদের সার্ভার/নীতিতে ঠিক করতে হবে)।
> প্রমাণের জায়গা: `04-security.md` এবং `docs/test-logs/`। **যা নেই তা "আছে" বলবেন না।** অডিটে সেটাই সবচেয়ে বড় ঝুঁকি।

---

## ক. পরিচয় যাচাই ও লগইন

| প্রশ্ন | উত্তর | অবস্থা |
|---|---|---|
| পাসওয়ার্ড কীভাবে রাখা হয়? | bcrypt hash (cost 10)। সরল পাসওয়ার্ড কোথাও রাখা হয় না, লগেও না। | ✅ |
| কেউ পাসওয়ার্ড অনুমান করলে? | ৫ বার ভুলে অ্যাকাউন্ট ১৫ মিনিট লক, এক IP থেকে ৩০ বার ভুলে অপেক্ষা। সব চেষ্টা `login_attempts`-এ। আমাদের টেস্টে ২৫ বার ভুলের পর আটকেছে। | ✅ |
| পাসওয়ার্ডের নীতি কী? | কোম্পানির সিদ্ধান্তে যেকোনো পাসওয়ার্ড চলে (ব্যবহারকারীর সুবিধার জন্য)। এর বদলে: ২৫ বার ভুল হলে লগইন আটকে যায়, এক অ্যাকাউন্ট এক ফোনে, পাসওয়ার্ড বদলালে অন্য সব সেশন বন্ধ, পাসওয়ার্ড bcrypt hash-এ রাখা, চাইলে fingerprint/passkey। | ⚠️ (জেনেশুনে নেওয়া ঝুঁকি) |
| Two-factor (2FA/MFA) আছে? | সাধারণ লগইনে TOTP/SMS 2FA **নেই**। বিকল্প: Passkey/Fingerprint লগইন (ফোনে hardware-সুরক্ষিত), মোবাইলে "একটি ফোন" নিয়ম, ই-স্বাক্ষরে ইমেইল OTP। | ⚠️ |
| পাসওয়ার্ড ভুলে গেলে? | ইমেইলে ৬ অঙ্কের কোড (১৫ মিনিট, ৫ চেষ্টা) অথবা HR অস্থায়ী পাসওয়ার্ড দেয়। দুটোতেই পুরোনো সব সেশন বন্ধ। কে অ্যাকাউন্ট আছে তা বোঝা যায় না। | ✅ |
| লগইন কতক্ষণ থাকে? | ওয়েবে ১২ ঘণ্টা বা ৬০ মিনিট নিষ্ক্রিয় হলে শেষ; অ্যাপে ৭ দিন বা ৩ দিন না খুললে। Superadmin বদলাতে পারে। | ✅ |
| চাকরি ছাড়লে বা সন্দেহ হলে লগইন বন্ধ হয়? | হ্যাঁ। ব্লক, পদত্যাগ/বরখাস্ত কার্যকর, বা Superadmin-এর "sign out" হলে সব সেশন সঙ্গে সঙ্গে বন্ধ (প্রতি রিকোয়েস্টে যাচাই)। | ✅ |
| পাসওয়ার্ড বদলালে চুরি যাওয়া সেশনের কী হয়? | বাকি সব সেশন বন্ধ হয় (যে সেশন থেকে বদলানো সেটা থাকে)। | ✅ |
| Single Sign-On আছে? | 360 ERP-এর সাথে SSO হস্তান্তর আছে (সার্ভার-টু-সার্ভার, গোপন চাবি ব্রাউজারে যায় না)। অন্য Identity Provider (Azure AD, Google) **নেই**। | ⚠️ |

## খ. অনুমতি ও গোপনীয়তা

| প্রশ্ন | উত্তর | অবস্থা |
|---|---|---|
| কে কী দেখবে তা কীভাবে নিয়ন্ত্রণ হয়? | তিন ভূমিকা (Superadmin/Admin/কর্মী) + ৪০ মডিউল + মডিউলের ভেতরে layer + বিভাগ-সীমা + কোম্পানি-সীমা। সব সার্ভারে প্রয়োগ হয় (UI লুকানো ছাড়াও API বন্ধ)। | ✅ |
| বেতনের তথ্য কে দেখে? | শুধু Payroll মডিউলের Admin। কর্মী শুধু নিজের payslip। টেস্টে কর্মী অন্যের payroll খুলতে পারেনি। | ✅ |
| একজন একাই বেতন বানিয়ে পরিশোধ করতে পারে? | না। HR বানায় → Audit অনুমোদন → Accounts পরিশোধ। যে বেতন চালিয়েছে/বদলেছে বা submit করেছে সে অনুমোদন দিতে পারে না; যে চালিয়েছে, submit বা অনুমোদন করেছে সে পরিশোধ করতে পারে না। Audit/Accounts "View only" layer পায় (দেখে, বদলাতে পারে না)। Audit Manager টেস্ট ৪৯/৪৯ পাস (`test-logs/2026-10-25/06-audit-manager-retest.log`)। ব্যতিক্রম: Superadmin। | ⚠️ |
| পদাধিকার বাড়িয়ে নেওয়া যায়? | কর্মী নিজের role বাড়াতে পারে না; Admin নিজেকে বেশি মডিউল দিতে পারে না; API দিয়ে নতুন Superadmin বানানো যায় না (সবই টেস্টে যাচাই)। | ✅ |
| একাধিক কোম্পানির ডাটা আলাদা থাকে? | হ্যাঁ, কোডে প্রতিটি SQL-এ কোম্পানির ফিল্টার বসে। (ডাটাবেস-স্তরে আলাদা স্কিমা নেই, একই ডাটাবেসে।) | ⚠️ |
| ব্যক্তিগত তথ্য (NID, ঠিকানা) কে দেখে? | Employees মডিউলের Admin সব কর্মীর NID দেখেন; Employee Directory-তে সবাই সবার ফোন নম্বর দেখে। নীতি ঠিক করা দরকার। | ⚠️ |
| লোকেশন ট্র্যাকিং কি সম্মতি ছাড়া? | না। আলাদা সুইচ (ডিফল্ট বন্ধ) ও ব্যবহারকারীকে নোটিশ ও সম্মতির পেজ। | ✅ |

## গ. ডাটা সুরক্ষা

| প্রশ্ন | উত্তর | অবস্থা |
|---|---|---|
| ট্রানজিটে (ইন্টারনেটে) এনক্রিপশন? | সার্ভার Nginx-এর পেছনে HTTPS-এ চালানোর কনফিগ আছে (`deploy/nginx.conf.example`), HTTPS হলে HSTS যায়। **সার্টিফিকেট বসানো আপনাদের কাজ।** | 🏢 |
| রেস্টে (ডাটাবেস/ডিস্কে) এনক্রিপশন? | অ্যাপ নিজে পুরো ডাটাবেস এনক্রিপ্ট করে না। নির্দিষ্ট সিক্রেট এনক্রিপ্ট/hash: মেইল পাসওয়ার্ড (AES-256-GCM), সব পাসওয়ার্ড (bcrypt), token/কোড (hash)। ডিস্ক এনক্রিপশন হোস্টিংয়ে। | ⚠️ 🏢 |
| SQL Injection থেকে সুরক্ষা? | সব query prepared statement। লগইনে injection চেষ্টা টেস্টে আটকেছে। | ✅ |
| XSS থেকে সুরক্ষা? | React নিজে escape করে; Notice-এর HTML সার্ভার ও ব্রাউজারে পরিষ্কার। টেস্ট: `<script>`/`onerror` ফেরে না। | ✅ |
| ফাইল আপলোড নিরাপদ? | আকার সীমিত (২৫–৩০MB), ছবির ধরন যাচাই। ডকুমেন্টের ধরন-যাচাই ও ভাইরাস স্ক্যান **নেই**। | ⚠️ |
| ভুল বা ডাটাবেসের ত্রুটি ব্যবহারকারী দেখে? | না। ডাটাবেসের বার্তা লুকানো, সংক্ষিপ্ত সাধারণ বার্তা যায়। | ✅ |
| এক কোম্পানির HR অন্য কোম্পানির কর্মীর তথ্য দেখতে পারে? | না। Admin Panel-এর কাজে id দিয়ে খুললেও শুধু চলতি কোম্পানির (বা সেখানে assign করা) কর্মী পাওয়া যায়; অন্য কোম্পানির ব্যাংক অ্যাকাউন্ট, বেতন, নাম পড়া/বদলানো আটকায় (টেস্ট `qa-companies` ১৮/১৮)। | ✅ |
| মাদার কোম্পানির HR কি sister company-গুলোর কাজও করতে পারেন? | হ্যাঁ, Superadmin প্রবেশাধিকার দিলে: company switcher-এ কোম্পানি বেছে, অথবা আলাদা অনুমতি "All companies mode" দিলে সব কোম্পানির কর্মীর রেকর্ড এক জায়গা থেকে। দুটোই Superadmin-এর হাতে, ডিফল্টে বন্ধ, আর বদল নিরীক্ষা লগে থাকে (টেস্ট `qa-group-hr` ২১/২১)। | ✅ |
| একসাথে দুবার ক্লিক করলে বেতন/বিল দুবার যায়? | না। অনুমোদন, বেতন পরিশোধ, বিল disburse, ঋণ অনুমোদন ডাটাবেসে শর্ত দিয়ে একবারই হয়; দ্বিতীয়টা 409 পায় (টেস্ট `qa-concurrency` ৯/৯)। | ✅ |
| গুরুত্বপূর্ণ রেকর্ড ভুলে মুছে যেতে পারে? | কর্মী মুছতে গেলে বেতন/সেবা-রেকর্ড থাকলে আটকায় (ডাটাবেসও আটকায়)। পরিশোধিত বেতন বদলানো যায় না। | ✅ |
| ব্যাকআপ? | সফটওয়্যারে ডাটাবেস ব্যাকআপের স্বয়ংক্রিয় ব্যবস্থা **নেই**। ফাইলও ডাটাবেসে, তাই ডাটাবেস ব্যাকআপই সব। MySQL dump/স্ন্যাপশট সময়সূচি আপনাদের ঠিক করতে হবে। | 🏢 ❌ |
| ডিজাস্টার রিকভারি (RTO/RPO)? | লিখিত পরিকল্পনা **নেই**। | 🏢 ❌ |

## ঘ. নিরীক্ষা ও লগ

| প্রশ্ন | উত্তর | অবস্থা |
|---|---|---|
| কে কী করেছে তার প্রমাণ থাকে? | লগইন চেষ্টা, পাসওয়ার্ড রিসেট, অ্যাক্সেস বদল, payroll-এ প্রতিটি লেখা, কর্মীর তথ্য বদল (আগে/পরে), বেতনের ব্যাংক অ্যাকাউন্ট বদল (কর্মীকে alert সহ), ই-স্বাক্ষর ঘটনা, MPR সম্পাদনা, Mail অ্যাডমিন কাজ। `04-security.md` §৮। | ✅ |
| সব ডাটা-পড়ার লগ আছে? | না। সব পেজ খোলার লগ নেই (শুধু Payroll-এ কে কোন পেজ খুলল আছে)। | ⚠️ |
| লগ কেন্দ্রীয়/অপরিবর্তনীয়? | আলাদা SIEM/অপরিবর্তনীয় লগ **নেই**। অ্যাপ লগ PM2-তে। | ❌ |
| লগ কতদিন রাখা? | `login_attempts` ৩০ দিন; বাকিগুলো মোছার স্বয়ংক্রিয় ব্যবস্থা দেখিনি (জমে থাকে)। নীতি ঠিক করা দরকার। | ⚠️ |

## ঙ. ই-স্বাক্ষর ও ডকুমেন্ট

| প্রশ্ন | উত্তর | অবস্থা |
|---|---|---|
| স্বাক্ষর কি আইনত বৈধ? | প্রযুক্তিগতভাবে: স্বাক্ষরকারী চেনা (OTP চালু করলে), ফাইলের SHA-256, সময়, ক্রম, QR দিয়ে যাচাই, ঐচ্ছিক PKCS#7 সার্টিফিকেট স্বাক্ষর। **আইনি বৈধতার জন্য** বাংলাদেশের CCA-অনুমোদিত সার্টিফিকেট কিনে (`ESIGN_CERT_FILE`) বসানো এবং আইনজীবীর মত লাগবে। বর্তমান সার্টিফিকেট self-signed হলে Adobe-এ "validity unknown" দেখাবে। | ⚠️ |
| স্বাক্ষরের পর ফাইল বদলালে ধরা যায়? | হ্যাঁ। সার্টিফিকেট স্বাক্ষরে এক বাইট বদলালেও PDF reader ধরে; `/verify` পেজেও ফাইল মেলানো যায়। | ✅ |

## চ. বাইরের সেবা ও তৃতীয় পক্ষ

| প্রশ্ন | উত্তর | অবস্থা |
|---|---|---|

1. **সবসময় প্রমাণ দেখান:** "আমরা নিরাপদ" বলার বদলে ফাইলের নাম বা টেস্ট লগ দেখান।
